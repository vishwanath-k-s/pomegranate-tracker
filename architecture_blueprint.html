▾ 1. Overview

The application manages end-to-end post-defoliation crop scheduling, real-time disease/pest epidemiology, FCO & elemental nutrient accounting, and FAO-56 drip irrigation across 1,500 Super Bhagwa pomegranate trees (planted 2024-09-20, $10 \times 8\text{ ft}$ spacing, $2 \times 8\text{ LPH} = 16\text{ LPH/plant}$ emitters) starting from the Week 1 Ethrel defoliation baseline on 2026-08-15 (0 DAD).

All client logic is bundled in a single zero-build file (index.html) using Tailwind CSS and @supabase/supabase-js@2. It communicates with a 10-table Supabase PostgreSQL backend, an automated daily 05:30 IST server-side engine (run_daily_orchard_engine), and the Open-Meteo Forecast & Historical Telemetry API, backed by an offline-first IndexedDB mutation outbox (HosahalliOfflineDB).

▾ 4. Core Agronomic, Weather & Mathematical Engines

4.1. 3-Tier Thermal Growing Degree Days (GDD Base 10°C / Cap 38°C)

Pomegranate phenology is driven by thermal heat accumulation rather than static calendar days. computeDailyGdd(tMax, tMin) implements the ICAR-NRCP / Syngenta Base-10°C model with an upper physiological cutoff at 38.0°C and a stomatal heat-arrest penalty above 38.0°C:

GDD_daily = max(0, ((min(T_max, 38.0) + max(T_min, 10.0)) / 2) - 10.0 - max(0, (T_max - 38.0) * 0.5))

getGddStageModel() combines three weather tiers to project exact start and end dates for all 6 Super Bhagwa stages (0–950, 950–1450, 1450–2150, 2150–2500, 2500–2800, 2800–3000 GDD): Tier 1 (Observed daily Open-Meteo temperatures from 2026-08-15 to todayYMD()), Tier 2 (15-day live Open-Meteo daily forecast), and Tier 3 (Hosahalli monthly historical baseline curve scaled by the current season's thermal anomaly factor).

4.2. 6-Threat Epidemiological Radar, Latent Carryover & Time-Decaying Shields

computeAllSixRisks() evaluates BLIGHT_SPOT, FRUIT_ROT, THRIPS_SCAR, FRUIT_BORER, MEALYBUG, and CRACKING on a 5%–100% scale using three biological layers:

Epidemiological Layer Function Mathematical & Biological Rule
1. 72h Microclimate Window evaluate72hEpidemiologicalWindow() Triggers when 72h mean RH $\ge 80\%$ and $T_{\max} \in [25.0^\circ\text{C}, 32.5^\circ\text{C}]$ for 3 consecutive days. Adds a +18% pre-lesion incubation bonus even with 0 mm rain and shortens recommended spray intervals to 4 days.
2. 6-Day Latent Carryover computeAllSixRisks() + wasThreatTreatedSince() Scans wState.history6d. If a weather spike occurred $d \in [1, 6]$ days ago and no guild-specific chemical (`doesItemCoverThreat`) was completed since that date, today's risk retains $\max(\text{InstantScore}, \text{PastPeak} - d \times \text{DecayRate})$.
3. Time-Decaying Knockdown Shield getShieldsActiveOnDate() + applyTimeDecayingShield() Evaluates guild-specific completed sprays (`copDays`, `funDays`, `thripsDays`, `borerDays`, `mealyDays`, `caDays`):
• Days 0–3: $\times 0.30$ (-70% knockdown → drops high risk to LOW)
• Days 4–6: $\times 0.50$ (-50% residual protection)
• Days 7–9: $\times 0.75$ (-25% tapering protection)
• Day 10+: $\times 1.00$ (shield expired).

4.3. 5-Parameter FAO-56 & ICAR-NRCP Drip Irrigation Engine

renderSeasonSprayAndDripGuides() keeps the 6-stage baseline table constant (14 L, 20 L, 26 L, 22 L, 16 L, 12 L/plant/day) while calculating Today's Live Weather-Adjusted Target from 5 parameters:

1. Hargreaves-Samani Daily Reference ET₀: ET0 = 0.0023 × R_a(month) × (T_mean + 17.8) × sqrt(max(4, T_max - T_min))
2. Smooth 72h VPD Modifier: vpdMult = clamp(1.00 + (60 - RH_72h) × 0.004, 0.88, 1.12)
3. Gross Daily Demand: Gross_L = round(ET0 × K_c(stage) × 4.79 m² × vpdMult)
4. 72h Infiltrated Rain Credit: First 2.5 mm/day is subtracted as surface dust evaporation. Infiltrated rain is weighted 80% Today + 50% Yesterday + 25% 2d Ago over a 2.0 m² root bulb (2.0 L/mm credit).
5. Runtime & Split-Pulse Guard: Runtime_mins = round((Net_L / 16 LPH) × 60). If Net_L < 4 L (unpressurized lateral floor) → 0 L. If Net_L ≥ 20 L → recommends 60% Morning + 40% Evening split pulses to prevent red-soil leaching.

▾ 5. Workflow state machine

Four stored task states in daily_task_queue.status plus two derived UI/recipe states. Stored tokens: PENDING DELAYED COMPLETED SKIPPED Derived states: PARTIAL (derived from item_status) AUTO-DEDUPLICATED (recipe adjusted)

Figure 3. Task status transitions and the handler functions that perform each transition. Item-level status lives in resolved_recipe[i].item_status; when some items are completed and others remain pending, the UI derives PARTIAL DONE and offers splitRemainingItemsToTomorrow().

Transition & Schedule Reconciliation Table

From → To Handler Function Side Effects on Schedule, Doses & Database
PENDING / DELAYED → DELAYED / PENDING applyScheduleShift(tk, date, mode, reason) Defaults to mode = "TRACK" (isolating Drip from Foliar). Walks all pending tasks on the same track from todayYMD() forward and enforces a minimum 5-day gap between Foliar/Copper cards and a minimum 2-day gap between Drip cards.
Curative Added / Shifted → Baseline Reconciled reconcileUpcomingBaselineFoliarAfterCurative() Finds any uncompleted baseline Foliar/Copper spray within -2 to +6 days of the curative spray, shifts it to curativeDate + 5 days (TRACK mode), strips duplicate salts/IRAC-FRAC groups, and injects BIO_ORTHOSILICIC if needed.
Curative Deleted → Baseline Restored deleteCustomTask(id) Deletes the SCOUTING_CURATIVE card and automatically restores any nearby deduplicated/shifted baseline spray back to its original baseline_schedule_template recipe and original date (if ≥ todayYMD()).
PENDING → COMPLETED (Drip Item) setItemStatus() / syncNextDripDoseForItem() Compares actual_total_3ac against suggestedTotal3Ac. If the user applied a surplus or deficit (≥0.5 kg), adjusts the next scheduled drip card's dose_per_acre (clamped between 0.5 kg/ac and 1.5× base dose).
PENDING → SKIPPED (Drip Item) computeSafeNextDripDose() Boosts the next scheduled drip card for that fertilizer by +50% (orig × 1.5 EC root-safety cap) to recover skipped nutrition without burning feeder roots.

▾ 6. Data storage & Offline Outbox (HosahalliOfflineDB)

Because mobile connectivity in the Hosahalli orchard can drop during field walks, the application uses a 3-tier storage hierarchy with synchronous memory mirroring and transactional coalescing.

▾ 8. 3-Gate Agronomic Safety & Resistance Model

Every chemical addition (addItemToTaskCard), store swap (openSwap / doSwap), manual log (saveManualActivity), and curative combiner run (queueCombinedSelectedRisks) passes through three deterministic safety gates:

Safety Gate Validator Function(s) Enforcement Rules
Gate P1:
Phenology & Residue		 checkPhenologyAndPhiLock(cat, dad, gdd) • Zero-Nitrogen Lock (ZERO_N_LOCK): Blocks any input with contains_nitrogen = true or n_pct > 0 once the orchard reaches 2,150 GDD (Stage C2 Color Lock) or 140 DAD to prevent chlorophyll re-greening of the rind.
• Pre-Harvest PHI Lock (PHI_LOCK): During late ripening (≥165 DAD or ≥2,500 GDD), blocks any pesticide whose phi_days exceeds the remaining days to the 2,800 GDD (190 DAD) harvest window.
Gate P2:
Tank-Mix & W-A-L-E-S		 validateCardCombinationRules()
checkPairCompatibility()
getWalesMixingGuide()		 • Drum Overload Cap: Maximum 3 pesticides per drum (max 2 Insecticides + 1 Fungicide, or 2 Fungicides + 1 Insecticide ONLY if 1 Fungicide is a multi-site contact FRAC-M01/M03/M04). Blocks dual systemic fungicides and duplicate IRAC groups.
• Chemical Precipitation Locks: Blocks Copper + Insecticides/Captan/Chelates, and blocks Drip Calcium Nitrate + Sulphates (00:00:50, MgSO4) or Phosphates (00:52:34).
• W-A-L-E-S Sequence: Sorts foliar drum mixing order automatically: 1. WSF/DF/WG/WP → 2. SP → 3. SC/OD/SL → 4. EC.
Gate P3:
21d Anti-Resistance		 checkRecentSprayResistance()
pickRotationSafeRecipe()
getSeasonSprayStats()		 • 21-Day Repeat-Salt / Group Alert: Scans completed tasks within ±25 days (excluding the card's own ID). Flags any repeated base salt (`normalizeSaltBase`) or single-site IRAC/FRAC group inline on the card and in the Swap Modal.
• Auto-Rotation on Smart Queue: Automatically substitutes recently sprayed salts with their top approved rotational alternative before inserting a curative card.
• Seasonal Cap Counter: Tracks cumulative sprays since 2026-08-15 against max seasonal limits (2 for single-site insecticides, 3 for fungicides, 6 for multi-site protectants).
